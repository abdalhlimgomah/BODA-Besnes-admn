دليل API تاجر — استخراج التوكن وتجديده

شرح كامل: استخراج التوكن، أين يُخزّن، كيف يتجدد تلقائياً، هيكل الملفات، والأوامر

استخراج يدوي أماكن التخزين التجديد التلقائي هيكل الملفات سير العمل

1 استخراج التوكن يدوياً من المتصفح

1.1 سجّل الدخول إلى تاجر

افتح taager.com في المتصفح وسجّل الدخول بحسابك (Google أو بريد إلكتروني).

1.2 افتح أدوات المطور

اضغط F12 (Windows) أو Cmd+Option+I (Mac).

1.3 اذهب إلى Application → Local Storage

اختر tab Application → من القائمة اليسرى Local Storage → اختر https://www.taager.com.

1.4 استخرج القيم الثلاث

المفتاحالمسمىملاحظات
tgr--usrAPI Key (JWT Token)قيمة طويلة تبدأ بـ eyJ. صالحة 24 ساعة.
tgr--usr-sSession Key32 حرفاً. يتغير بتسجيل الخروج.
داخل tgr--usrTaager IDرقم ثابت. جرب jwt.io لاستخراجه.
💡 أسهل طريقة: في صفحة "إدارة توكن تاجر" في لوحة التحكم، الصق قيمة tgr--usr كاملة في صندوق "استخراج البيانات من JSON" واضغط استخراج — يملأ الحقول تلقائياً.
⚠️ التوكن ينتهي بعد 24 ساعة. يجب تجديده يومياً. لهذا صممنا التجديد التلقائي (انظر أدناه).

2 أماكن تخزين التوكن — 3 مستويات

التوكن يُخزّن في 3 أماكن مختلفة لأغراض مختلفة:

المستوى 1 — ملف ثابت
auth.config.js
قيم افتراضية. يُحدَّث عند تشغيل Python script.
المستوى 2 — قاعدة بيانات
app_settings table
يُعدَّل من لوحة التحكم. يُجلب عند تحميل الصفحة.
المستوى 3 — سرّي (آمن)
Supabase Secrets
لـ Edge Function فقط. يُحدَّث عبر CLI أو Python script.

2.1 ملف assets/js/auth.config.js

ملف ثابت يحتوي القيم الافتراضية. عندما يشغّل المستخدم taager_token_refresh.py، يقوم الـ script بتحديث هذا الملف باستخدام Regex (re.sub) للبحث عن window.TAAGER_API_KEY و window.TAAGER_TAAGER_ID و window.TAAGER_SESSION_KEY واستبدالها بالقيم الجديدة.

2.2 جدول app_settings في Supabase

هذا جدول في قاعدة البيانات (key-value store). عندما تحفظ البيانات من صفحة "إدارة توكن تاجر" (admin-taager-token.html)، تُخزَّن في هذا الجدول عبر upsert.

عند تحميل أي صفحة تستخدم API تاجر، الدالة getTaagerCreds() تجلب القيم من هذا الجدول وتخزّنها في window لتستخدمها بقية الدوال.

2.3 Supabase Secrets (لـ Edge Function)

الـ Edge function taager-proxy تحتاج التوكن لتتصل بـ Taager API نيابة عن المتصفح. القيم تُخزَّن كـ supabase secrets ولا يمكن لأي مستخدم الوصول إليها (حتى من لوحة التحكم).

الأسماء الدقيقة للـ Secrets:

  • TAAGER_JWT_TOKEN — التوكن نفسه
  • TAAGER_TAAGER_ID — معرف التاجر
  • TAAGER_SESSION_KEY — مفتاح الجلسة
  • TAAGER_SYNC_SECRET — مفتاح سري إضافي للمزامنة (اختياري)
ملاحظة: وجود SUPABASE_URL و SUPABASE_SERVICE_ROLE_KEY كـ Secrets ضروري لكتابة المنتجات في قاعدة البيانات مباشرة من Edge Function.

3 التجديد التلقائي — taager_token_refresh.py

سكربت Python يستخدم Selenium (متصفح آلي) لتسجيل الدخول إلى تاجر واستخراج التوكن الجديد. صمم ليشتغل يومياً عبر Scheduled Task في Windows.

3.1 ماذا يفعل السكربت بالتفصيل؟

  1. فحص التوكن الحالي — يشغل supabase secrets list ويفحص JWT في TAAGER_JWT_TOKEN. إذا تبقى أكثر من 4 ساعات، يتخطى (--force يُجبره على التجديد).
  2. فتح Chrome — يستخدم webdriver-manager لتحميل ChromeDriver المناسب، ويفتح Chrome مع user-data-dir مخصص (عشان يحفظ الجلسات).
  3. محاولة headless — يحاول أولاً في وضع الخلفية (--headless) ويستخرج التوكن عبر JavaScript (localStorage.getItem('tgr--usr')).
  4. تسجيل الدخول اليدوي — إذا فشل الـ headless، يفتح Chrome ظاهر (visible) وينتظر المستخدم يسجل دخول لمدة 5 دقائق.
  5. استخراج البيانات — ينفّذ driver.execute_script() لقراءة localStorage واستخراج accessToken و taagerId و sessionKey و email.
  6. فك JWT — يفك base64 من التوكن ويعرض تاريخ الانتهاء في الـ log.
  7. تحديث Supabase Secrets — يشغّل الأمر supabase secrets set TAAGER_JWT_TOKEN="..." TAAGER_TAAGER_ID="..." TAAGER_SESSION_KEY="...".
  8. تحديث auth.config.js — يقرأ الملف ويستخدم Regex لاستبدال القيم القديمة بالجديدة.
  9. تسجيل الـ log — يكتب في ملف taager_refresh.log كل الخطوات مع توقيت.

3.2 المتطلبات

  • Python 3.7+ مثبت على الجهاز
  • مكتبة selenium و webdriver-manager — يتم تثبيتها بـ pip install selenium webdriver-manager
  • Supabase CLI مثبت — يُثبّت عبر npm install -g supabase
  • Node.js — ضروري لتشغيل Supabase CLI
  • حساب تاجر مسجل الدخول في Chrome (أو على الأقل مرة واحدة)

5 سير العمل — كيف يتصل المتجر بـ API تاجر

🔁 مسار الاتصال (مسارَين):

المسار الأول — Edge Function (مفضّل):
المتصفح ← fetch(taager-proxy?action=products) ← الخادم يُمرّر الـ JWT من Supabase Secrets ← Taager API ← يُعالج ويعيد المنتجات ← يُحدّث قاعدة البيانات مباشرة ← يرجع للمتصفح

المسار الثاني — مباشر (احتياطي):
المتصفح ← fetch(Taager API) مع Authorization: Bearer JWT من app_settings ← Taager API يرجع منتجات ← يُعالج في المتصفح ويُحدّث قاعدة البيانات

5.1 خطوة بخطوة — عند فتح صفحة تدقيق تاجر

  1. تحميل الصفحة: loadProducts() تجلب كل المنتجات من Supabase (taager_products) وتظهرها في الجدول.
  2. عرض الإحصائيات: renderStats() تحسب عدد المنتجات الناقصة صور/تفاصيل/أفكار/طريقة استخدام.
  3. ضغط زر جلب: المستخدم يضغط "صور" أو "تفاصيل سريعة" أو "أفكار محتوى" إلخ.
  4. جلب API: fetchAllTaagerProductsViaEdge('EG') — يحاول Edge Function أولاً (30 ثانية timeout). لو فشل، fetchTaagerAPIDirect() — مباشر مع timeout 10 ثواني.
  5. بناء المطابقة: يُبنى apiLookup يربط كل ID ممكن (variantId, id, productId, sku, code, ...) بالمنتج من API.
  6. المعالجة واحداً واحداً: لكل منتج في قاعدة البيانات، يبحث عن مطابق في API، ثم يُحدّث الحقل المطلوب.

5.2 ماذا لو فشل كل شيء؟

إذا رجع API تاجر [] فاضي (كما حصل لنا)، وأظهرت الشاشة "تم تحديث 0 منتج (تخطي X بدون تطابق)"، فالسبب غالباً:

  1. التوكن منتهي الصلاحية — شغّل taager_token_refresh.py (أو جدد يدوياً من المتصفح)
  2. Session Key خطأ — إذا تغيرت الجلسة، الـ Session Key يختلف. جدّد من المتصفح.
  3. الـ Edge Function مش منشور — شغّل supabase functions deploy taager-proxy --no-verify-jwt
⚠️ تذكير: آخر مرة جُدّد فيها التوكن كانت في 10 يوليو 2026. إذا مرّت 24 ساعة، جدد الآن.

5.3 مزامنة Edge Function بعد التجديد

بعد تجديد التوكن، يجب مزامنته مع Edge Function. السكربت taager_token_refresh.py يفعل ذلك تلقائياً (supabase secrets set).

إذا أردت يدوياً:

supabase secrets set \
  TAAGER_JWT_TOKEN="<eyJ...>" \
  TAAGER_TAAGER_ID="<2226119>" \
  TAAGER_SESSION_KEY="<abc123...>"

supabase functions deploy taager-proxy --no-verify-jwt

6.3 فك JWT

def decode_jwt(token):
    payload_b64 = token.split(".")[1]
    payload_b64 += "=" * (4 - len(payload_b64) % 4)
    return json.loads(base64.urlsafe_b64decode(payload_b64))

def token_remaining_seconds(token):
    payload = decode_jwt(token)
    return float(payload["exp"]) - time.time()

def has_fresh_token(token, min_remaining=300):
    return token_remaining_seconds(token) > min_remaining

يقسّم JWT إلى 3 أجزاء (header.payload.signature)، يفك base64 من الجزء الثاني (payload)، ويقرأ exp (تاريخ الانتهاء).

6.5 تشغيل Chrome

def build_driver(headless=True):
    opts = Options()
    if headless: opts.add_argument("--headless")
    opts.add_argument(f"--user-data-dir={PROFILE_DIR}")
    return webdriver.Chrome(service=Service(ChromeDriverManager().install()), options=opts)

--user-data-dir يخلّي Chrome يحفظ الجلسة (الكوكيز والتسجيل) في مجلد ثابت. أول مرة يحتاج تسجيل دخول يدوي، بعدها يشتغل في الخلفية.

6.6 استخراج التوكن من المتصفح

def extract_token(driver):
    return driver.execute_script("""
        const raw = localStorage.getItem('tgr--usr');
        const data = JSON.parse(raw).data || {};
        const sessionRaw = localStorage.getItem('tgr--usr-s');
        const sessionKey = sessionRaw ? JSON.parse(sessionRaw).data || '' : '';
        return {
            accessToken: data.accessToken || '',
            taagerId: String(data.id || ''),
            sessionKey: sessionKey,
            email: data.email || ''
        };
    """)

ينفّذ JavaScript داخل المتصفح لقراءة localStorage. يستخرج accessToken من tgr--usr و Session Key من tgr--usr-s.
